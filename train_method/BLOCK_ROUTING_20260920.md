# Texture block routing audit

Implemented `block_threshold_point_selection_v2`. Default threshold is 0.30,
strictly greater, measured over all sparse context rows including the halo.

* High visibility: conditional branch for the full block.
* Zero visibility: baseline endpoint velocity for steps 0..n-1; unconditional
  velocity thereafter.
* Low nonzero visibility, including equality with threshold: separate full
  conditional and unconditional forwards on identical context and x_t at every
  step. Select conditional v for visible owners. Select baseline endpoint v
  for hidden owners during the prefix, unconditional v afterwards. During the
  prefix the unconditional forward is computed but its output is unused.
* Both image global tokens and local projection features are zero in the
  unconditional forward; geometry concat remains. Conditional retains existing
  CFG behavior (separate positive/negative evaluations, homogeneous each time).
* Overlapping z-block owner contributions are averaged before updating x_t.
  XY crops retain the existing unique-owner policy; halo rows are context only.
* Missing baseline guide coverage raises an error instead of silently choosing
  unconditional early. Use guide preparation with mesh-face fallback.
* n=0 now means no guidance prefix. Use --all-conditional for the control.
  Old sampler manifests are rejected. Use new output directories.

First-stage mapping now uses image context 2048/stride 1024 on the internal
4096 canvas: 3x3 crops, C128 z context 32/stride 16, 7 segments, 63 candidates.
Second-stage mapping remains 16x7 C256 candidates. Empty blocks are skipped.
Existing cached mappings are not regenerated by these source edits.
The current texture-only experiment operates on final C256 geometry; this
change does not add a new intermediate C128 texture-generation stage.

CPU audit of the existing turtle C256 mapping: 112 candidates, 88 nonempty,
47 high, 40 low mixed, 1 fully hidden. Of 156847 hidden points, 64252 receive
conditional updates from high blocks under the requested rule. Setting
--visibility-threshold 1.0 removes those direct conditional owner updates.
It does not guarantee absence of indirect shared-state/decoder influence.

Validated with four synthetic routing/layout tests (n=0..4, all 12 steps,
exact threshold, overlapping owner counts, missing guide support, explicit
control, 3x3x7 layout), four visibility-guidance tests, and two synchronization
tests. No new GPU texture render was produced by this audit/change.

Core implementation: train_method/texture_block_routing.py.
Entrypoint: python -m train_method.run_point_visibility_texture --gpu 1
(supply a prepared --root and fresh --output-dir).
Audit: python -m train_method.audit_texture_block_routing --root PREPARED_ROOT
--output REPORT.json.
